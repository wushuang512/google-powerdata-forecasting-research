# 从这里开始

最新报告：**Google PowerData 2019 算电融合与 ClusterData 扩展研究汇报.docx**。

已实际训练、回测、部署。第五轮冻结主方案的次日 WAPE 为 **2.3742%**，此前最优为 2.3848%，相对下降 0.44%；相对最早旧组合 2.4165% 下降 1.75%。联合日期与集群的改进区间跨零，目前仍没有大幅、显著、跨月可靠提升的证据。主方案是原基础组合与正则残差校准各占一半。

用户提出的 RevIN、多尺度时频、双编码器、交叉注意力、稀疏 MoE、联合代理输出、分位头已经实现。两随机种子平均 WAPE 2.9029%，曲线精度低于主方案。第五轮的 W 是历史生产功率代理，不是真实算力；资源状态随后从 ClusterData 加入独立实验。不能把多个分支拼接称为一个已胜出的完整算电模型。

ClusterData 官方完整机器事件和属性共 32 个 JSON/Parquet 文件已下载，共 226,995,708 字节。一个官方使用记录 JSON 分片 432,275,123 字节，共 4,483,198 条；其中任务记录仅 36,596 条，覆盖不均，不能代表完整 CPU 负载。

第六轮用完整机器状态建模，入选家族的纯候选 WAPE 2.3668%，但开发期一个标准误规则选择新增权重 0，所以主方案仍为 2.3742%。同正则强度不加资源的对照为 2.3698%，不能把全部改善归因于资源。第七轮加入部分任务 CPU/内存样本没有可靠收益。完整使用记录的较小 Parquet 版本仍约 3.09 TiB；目前没有完成全量使用表下载，没有提交 BigQuery 任务。完整提取 SQL 已准备，须有可用项目和账号，先估算费用再授权执行。

## 运行入口

01：当前冻结主方案，输出 `experiment/round5/results/selected_deployment_origin31_1day.csv`。
02：保留 TiRex 七天方案，WAPE 2.8803%。
03：最早旧等权组合。04：第二轮峰值探索。05：第四轮七天组合对照。
06：第五轮融合网络探索，输出两种子的联合功率/生产功率代理预测与校准区间。
07：第六轮资源状态纯候选，验证规则未推荐替换主方案。
08：第七轮选中的对照家族；部分算力样本未获选，输入范围以冻结配置为准。

默认输入截至 **2019-05-31**，输出 **2019-06-01**，不是今天的实际负荷。本数据没有六月真值。这些程序面向已有 57 域 31 天结构，不能直接用任意新文件替换而不做适配。完整模型、依赖和结果都保留在本桌面目录。

## 关键核查

各轮 `docs/protocol.json`、`results/selection.json` 与 SHA256 记录选型，逐点与逐域分数保留。
`round5/results/verification.json` 是输入因果性、训练截止日期、组合、量纲、分位顺序和微调前向一致性检查，不是无过拟合证明。
`google-clusterdata-2019/results/mapping_audit.json`：55 域可关联，i、j 缺资源数据；c 中机器 102、124 的供电域映射歧义，已排除。
第六轮更正前的结果归档在 `results_before_mapping_correction`，更正不改变原冻结配置和权重。
`usage_sample_audit.json`：只有部分样本，未知抽样概率。第七轮不把缺失当真实零负载。
`docs/official_sizes_by_format.json`：JSON 与 Parquet 为不同导出格式，不可合并后重复计数。
`docs/bigquery_execution_status.json`：全量查询尚未执行，也没有费用估算结果。

同一个月已被多轮查看，当前测试不能视为新独立样本。CPU 单位是 NCU、内存按全局最大机器归一化，功率是容量利用率；没有实际 kW/MW，不能宣称实际电量守恒。机器状态是调度容量及可用性，不等于任务使用率。
