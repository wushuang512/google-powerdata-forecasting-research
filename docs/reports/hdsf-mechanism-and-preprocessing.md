主要原因及已有证据

分时使用专家。24小时前半天主要由Chronos-2和Toto2.0预测，后半天主要由两种TimesFM3模式预测；总改善的约86.52%发生在后半天。同一成员池中，分段优于等权平均及整段共享权重。

7天日均更稳。每日平均水平MSE下降6.35%，日内形状MSE反而上升1.14%；历史水平与日型平滑平均占29.01%权重，删除后日均WAPE变差。这解释了日均优势大于完整曲线优势。

成员误差有限互补。非负组合能抵消部分一高一低的误差，但主要成员残差相关仍约0.93至0.96，所以改善有限；24小时本地LightGBM成员平均仅占0.63%，不是主要来源。

证据边界：同月测试多轮查看、7天窗口重叠，探索置信区间跨零；峰值、cell-a五域等仍有退步。结论为当前回测中的局部优势，未证明独立月份的全面领先。

PowerData原始字段分别表示什么

主数据为2019年5月31天、10个cell、57个供电域，其中55个传统PDU、2个MVPP。57份功率CSV加1份机器映射CSV，各自GZIP压缩；每域8928条5分钟记录，共508896条。原始raw字节保持不变，csv目录仅解压。

| 原始字段 | 类型与单位 | 含义 | 实际用途 |
| --- | --- | --- | --- |
| time | UINT64 微秒 | 5分钟平均功率窗口的起点；相对trace时间，不是Unix时间戳。600000000对应2019年5月1日00时PT。 | 排序 聚合 定位日期 |
| cell | 字符串 | 匿名集群标识，如a。不能据此推断真实地理位置。 | 分组与元数据 |
| pdu | 字符串 | 匿名供电域标识，如pdu6或mvpp1；与cell共同确定一条序列。 | 序列识别与设备类型 |
| measured_power_util | 小数 利用率 | 该5分钟窗口总功率除以本域容量，包含机房冷却等非IT设备。0.75表示约75%容量利用。 | 预测目标与历史输入 |
| production_power_util | 小数 利用率 | 归于生产工作负载的估算功率；官方用CPU利用率及机器闲忙功率等估计，含非IT功率分摊。不是实测CPU或NCU。 | local24历史代理特征 |
| bad_measurement_data | 布尔值 | 总功率质量标记。本研究按官方Notebook处理：true为坏点，false可用，并同时检查数值有限。 | 评分掩码与聚合 |
| bad_production_power_data | 布尔值 | 生产功率质量标记，同样true为坏点；不自动等同于总功率无效。 | 生产代理独立处理 |

| --- | --- |
| machine_id | 匿名机器ID，按cell和machine_id连接，避免跨cell同名ID混淆。 |

功率原始数据实际做了哪些处理

1 读入与排序。解压后按cell与pdu识别序列，按time升序；检查时间唯一、5分钟等间隔及57域对齐。原始行序并非时间序，raw文件不改写。

2 质量筛选。总功率和生产功率分别按自身bad标记及数值有限性筛选。没有按测试结果删异常，也没有把缺失统一改成0。

3 五分钟聚合到十五分钟。连续3条记录合为一块，取有效点平均，标签保留块起点；每天288点变96点。

4 输入与评分分开。部分坏点用剩余好点均值作历史输入，target_valid仅在3点均有效时为true；坏块不评分。

5 整块缺失的处理分支。若3点全坏，代码取块前最后12个有效原始点中位数；本次0块触发。

6 生产代理补值。为空块另建production_causal_median，用块前最后12个好点中位数；无历史保留NaN，特征层再按前一天同刻向前补。原production数组不覆盖。

7 单位与因果边界。目标保持官方利用率，未统一再做Min-Max或换成kW；成员内部处理由原生实现决定。外部补值和特征只读已完成历史。

| --- | --- |
| 总功率坏点 | 24 / 508896 原始点 |
| 含坏点的15分钟块 | 24块 全部为部分坏点 |

| 生产功率坏点 | 116517原始点 约22.90% |

处理后的字段怎样进入模型

基础模型读历史实测功率，local24构造64项历史特征。下表为派生量，完整名称与解释见本报告证据目录的字段字典CSV。

CPU与资源记录实际怎样聚合

按cell和machine_id连接PDU，排除归属歧义；只保留JOB、可映射机器、有效非负CPU/内存、0至300秒窗口和月内时间。每个窗口按结束时间分配到15分钟区间，CPU和内存乘窗口秒数再除900后求和。未按区间真实重叠长度拆窗，可能有不足5分钟对齐偏差。

| CPU聚合后的字段 | 实际定义 |
| --- | --- |
| completed_job_cpu_NCU | 该区间JOB的平均CPU使用加权和，即逐窗CPU×时长/900求和。PDU总量可大于1，不能当kW。 |
| completed_job_memory_normalized | 同样按时长加权的JOB归一化内存使用总量，不能直接换算GB。 |
| job_window_equivalent | 窗口时长/900之和，表示JOB窗口等效量；不是CPU方差或独立任务数。 |
| job_window_count | 纳入该区间的JOB窗口记录数；同一任务可出现多窗，不是去重任务数量。 |
| sample_rate_duration_sum | 采样频率乘时长后求和，用于估计采样覆盖。 |
| duration_seconds_sum | 纳入窗口的时长秒数总和；与上一项相除可得到平均采样频率。 |

机器事件按time排序，各cell单独维护状态，只处理区间终点之前的事件并向前保持状态；REMOVE令不可用，ADD/UPDATE更新容量。缺容量时保留既有已知容量。没有拿未来事件回填过去。以下比例均以可确定归属的映射机器数为分母。

真实CPU只覆盖a五域，其他52域的CPU数组0为缺失占位，不是实测CPU为0；资源数据不覆盖i/j两个MVPP。JOB-only遗漏alloc层额外开销与未监控工作负载；固定映射无生效日期。上述限制会影响算电协变量研究，不能据此把功率与CPU建立完整物理守恒。

统一评价与研究结论的边界

与9月28日评价保持一致的计算方式

曲线WAPE：每个PDU在有效点上，绝对误差总和除以真实值绝对总和并乘100%，再对57域等权平均。24小时用9个起报，7天用3个起报；项目原公布的全部点池化WAPE只作独立复现核对，不替换本报告分数。

MAE、RMSE、APE95及2%/5%命中使用相同有效点。每日均值要求96点均有效，完整日记录为24小时508条、7天1187条；重复目标日不是独立样本。

峰值MAPE每天在有效点中取真值和预测最大值比较，峰时取首个最大值。日均利用率不是日电量kWh；历史基线为前一天同刻与前3天同刻均值。

经验80%区间仅由开发残差10/90分位校准。HDSF覆盖率为24小时75.568%、7天76.009%，未达到80%；宽度与Winkler80仍按统一定义计算。

结果应怎样理解

开发期只有4个24小时起报、2个7天起报，7天窗口重叠。日期配对bootstrap改善区间分别为−0.016550至+0.093224、−0.056384至+0.072188个百分点，均跨0。源设计明确接触过历史测试，本地同月测试也多轮查看；缺少真正独立的确认月份。

非负共享权重提供参数限制，不能保证没有过拟合。原流程同时约束峰值、分组和偏差，HDSF主要优化池化绝对误差；统一评分相同，开发目标不同。两种历史无效值处理也有差异，所以跨旧新方案总增益不能全部归因为融合。

本次仅核查并重排报告，冻结选择、部署、原始数据和评价实现保持原样。独立确认后才可判断分时专家与7天水平稳定化的泛化优势。
